# Pruebas del 2026-11-16

Registro de la primera versión de este repositorio: la capa antialucinación,
separada del agente de criptomonedas para que sirva en cualquier rubro.

## De dónde viene

La capa se escribió y se probó dentro de
[anti-hallucination-crypto-agent](https://github.com/Jegoba90/anti-hallucination-crypto-agent),
y sale de ahí tal como estaba en el commit `8bc7b5b` (su release v1.4.0): el
paquete `antihallucination/`, sus tests (sin el prefijo `test_ah_`), las
respuestas reales de un modelo y el ejemplo de ventas. Su registro de pruebas
anterior, con el detalle de cada corrida, está en
[docs/pruebas-2026-11-16.md de ese repositorio](https://github.com/Jegoba90/anti-hallucination-crypto-agent/blob/master/docs/pruebas-2026-11-16.md).

Lo nuevo de este repositorio:

- Se instala con `pip`: `pyproject.toml`, el comando `antihallucination` y el
  marcador `py.typed` para quien lo use con un verificador de tipos. Las
  comprobaciones solo usan la biblioteca estándar; httpx viene para los modelos
  compatibles con OpenAI y el SDK de Anthropic es un extra (`[claude]`).
- Dos ejemplos de otros rubros, en inglés: métricas mensuales de un SaaS y un
  resumen de tickets de soporte que cita cada ticket. Un test fija lo que
  muestra cada ejemplo.
- Un README escrito para cualquier rubro, sin nada de criptomonedas.
- Un CI con tres trabajos: los tests en Python 3.11, 3.13 y 3.14; solo las
  dependencias que trae `pip install`; y el paquete instalado, usado desde
  fuera del repositorio.

## La prueba con un modelo real

`openai/gpt-oss-120b`, en Groq, escribió cuatro borradores del informe de
ventas. No tecleó ninguna cifra. En el primero se coló una oración sin datos,
«El desempeño general se mantiene dentro de los parámetros esperados», y de ahí
salió la regla de que toda oración debe llevar un dato o citar una fuente; los
tres borradores siguientes salieron enteros. Los cuatro están en
`tests/fixtures/real_model/groq_2026-11-16.json` y se juzgan en cada corrida de
tests.

## El servidor MCP

Para que la capa sirva a quien no programa: un asistente compatible con MCP
(Claude Desktop, Claude Code u otros) redacta, y el servidor escribe las cifras
y comprueba cada oración. No llama a ningún modelo ni a la red.

- Se escribió sobre el SDK oficial `mcp` 2.3.0, revisado instalado: en la 2.x
  `FastMCP` pasó a llamarse `MCPServer`, y un error común llega al cliente sin
  su motivo, por eso los errores de datos salen como `ToolError`.
- Cuatro herramientas de solo lectura: `prepare_report` (marcadores y reglas,
  sin ninguna cifra), `compose_report`, `verify_text` y `check_receipt`.
- En un chat el asistente ya vio las cifras, así que el encargo le prohíbe
  teclearlas en lugar de decirle que no se las muestran.

| Comprobación | Resultado |
|---|---|
| 8 tests con el cliente oficial del SDK, conectado en el mismo proceso | Las cuatro herramientas, el encargo sin cifras, el texto que publica, los errores de datos legibles y el recibo que se verifica y se repite |
| El mismo cliente lanzando el servidor por stdio, como un asistente | Ve las cuatro herramientas |
| El paquete instalado con el extra `[mcp]` en un entorno limpio | El comando `antihallucination-mcp`, manejado por stdio, auditó el resumen de tickets: detectó el 32 que el ticket no dice (dice 23) y la causa inventada, y publicó el título del ticket en su lugar |

El CI repite la última prueba en cada push, con el paquete instalado.

El primer push del servidor (`4247776`) falló en Python 3.11, la versión que
no está instalada en la máquina donde se escribió: pydantic, que arma los
esquemas de las herramientas, exige `typing_extensions.TypedDict` antes de
Python 3.12. Corregido en `ab593c7`, con el CI en verde en 3.11, 3.13 y 3.14
(218 tests cada uno), sin los extras (201 y 2 salteados) y con el paquete
instalado manejado por stdio.

## El servidor MCP dentro de Claude Code

Con el paquete publicado en PyPI, siguiendo el README tal cual: `pip install
"antihallucination[mcp]==0.2.0"` en el Python de la máquina y `claude mcp add
--transport stdio --scope user anti-hallucination -- python -m
antihallucination.mcp_server`. `claude mcp get` lo mostró conectado. Después,
dos sesiones nuevas de Claude Code sin pantalla (`claude -p`), con permiso solo
para las cuatro herramientas, recibieron cifras de ventas de una tienda.

| Pedido | Resultado |
|---|---|
| Informe de octubre con `prepare_report` y `compose_report` | Tres frases, ninguna eliminada ni reemplazada. No dijo que las ventas subieron, porque la variación no estaba entre los datos |
| El mismo informe y `check_receipt` | Recibo `verified` y `reproduced` |
| `verify_text` sobre un texto ajeno con un 20 % y 9 devoluciones | Rechazado: ni 20 % ni 9 salen de los datos (la subida es 16,1 % y las devoluciones fueron 19) |

Lo que encontró la segunda sesión: para escribir que las ventas subieron un
16,1 %, el modelo calculó la cifra él mismo y la pasó a la herramienta como un
dato más. Lo dijo en su respuesta, y la cuenta es correcta, pero el recibo
salió `verified` igual: la capa comprueba que el texto coincide con los datos
que recibe, no de dónde salieron. Desde un asistente, los datos los pasa el
modelo.
